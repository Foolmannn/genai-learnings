**Temperature** controls **randomness** in a language model’s output. It changes how the model chooses the next token (word/subword) from possible candidates.

Think of the model assigning probabilities:

| Token    | Probability |
| -------- | ----------- |
| "cat"    | 0.60        |
| "dog"    | 0.25        |
| "rabbit" | 0.10        |
| "car"    | 0.05        |

Temperature modifies these probabilities **before sampling**.

### Low temperature (≈ 0–0.3)

The model becomes **more deterministic** and prefers high-probability words.

Example prompt:

> "The capital of France is"

Temperature = **0**

Output:

> "Paris"

Repeated runs:

> Paris
> Paris
> Paris

Characteristics:

* More predictable
* More factual (often)
* Less creative
* Good for:

  * Coding
  * Summaries
  * Explanations
  * Classification
  * Data extraction

---

### Medium temperature (≈ 0.5–0.8)

Balanced between consistency and creativity.

Prompt:

> "Write a title for a blog about machine learning"

Temperature = **0.7**

Possible outputs:

* "Machine Learning Explained for Beginners"
* "Understanding ML: From Data to Decisions"
* "Your First Step into Machine Learning"

Characteristics:

* Natural variation
* Good for general chat
* Often default setting

---

### High temperature (≈ 1–2+)

The model explores lower-probability choices.

Prompt:

> "Describe the moon"

Temperature = **1.5**

Possible outputs:

* "The moon hangs like an ancient lantern..."
* "A silent witness drifting across cosmic tides..."

Characteristics:

* More creative
* More diverse
* More unexpected
* Higher chance of nonsense or hallucinations

Useful for:

* Story writing
* Brainstorming
* Poetry
* Creative ideas

---

## Mathematical intuition

Temperature changes probabilities using:

[
P_i' = \frac{e^{z_i/T}}{\sum_j e^{z_j/T}}
]

where:

* (z_i) = logits (raw scores)
* (T) = temperature

When:

* (T < 1): distribution becomes **sharper**
* (T = 1): original probabilities
* (T > 1): distribution becomes **flatter**

Example:

Original:

| Token | Prob |
| ----- | ---- |
| A     | 0.8  |
| B     | 0.15 |
| C     | 0.05 |

After **T=0.2**:

| Token | Prob  |
| ----- | ----- |
| A     | ~0.99 |
| B     | ~0.01 |
| C     | ~0    |

After **T=2**:

| Token | Prob  |
| ----- | ----- |
| A     | ~0.55 |
| B     | ~0.28 |
| C     | ~0.17 |

Higher temperature → weaker preference for top token.

---

## Important misconception

**Lower temperature ≠ always more accurate**

Temperature only changes **sampling behavior**. If the model lacks knowledge or reasons incorrectly, temperature 0 can still produce wrong answers—just more confidently and consistently.

---

## Typical settings by task

| Task             | Recommended Temperature |
| ---------------- | ----------------------- |
| Code generation  | 0–0.2                   |
| Math             | 0–0.3                   |
| Summaries        | 0.2–0.5                 |
| Chatbots         | 0.5–0.8                 |
| Brainstorming    | 0.8–1.2                 |
| Creative writing | 1–2                     |

---

### Example with coding

Prompt:

> "Write Python code to reverse a string"

Temperature = 0:

```python
s[::-1]
```

Temperature = 1:

```python
''.join(reversed(s))
```

Temperature = 1.5:

```python
def reverse(x):
    return x[-1::-1]
```

All valid, but more variation appears as temperature increases.

---

Temperature affects **how adventurous the model is when choosing outputs**, not how much it "knows."
