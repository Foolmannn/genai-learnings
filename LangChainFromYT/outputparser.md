In LangChain, **Output Parsers** are used to convert the raw text generated by an LLM into a structured format such as JSON, lists, dictionaries, Pydantic objects, etc.

They help solve a common problem:

> LLMs generate text, but applications often need structured data.

---

# Why Output Parsers?

Without an output parser:

```python
response = llm.invoke("Give me name and age of a person")

print(response)
```

Output:

```text
Name: John
Age: 25
```

You would need to manually extract the values.

With an output parser:

```python
{
   "name": "John",
   "age": 25
}
```

which is much easier for programs to use.

---

# Types of Output Parsers

## 1. StrOutputParser

Returns plain text.

```python
from langchain_core.output_parsers import StrOutputParser

parser = StrOutputParser()
```

Example:

```python
chain = prompt | llm | parser

result = chain.invoke({"topic": "AI"})
print(result)
```

Output:

```text
Artificial Intelligence is ...
```

This is the simplest parser.

---

## 2. JsonOutputParser

For structured JSON responses.

```python
from langchain_core.output_parsers import JsonOutputParser
```

Example:

```python
parser = JsonOutputParser()

prompt = PromptTemplate(
    template="""
    Answer in JSON format.
    Question: {question}
    """,
    input_variables=["question"]
)

chain = prompt | llm | parser
```

Output:

```python
{
    "answer": "Paris",
    "country": "France"
}
```

---

## 3. PydanticOutputParser

Converts output directly into a Pydantic model.

### Define schema

```python
from pydantic import BaseModel, Field

class Person(BaseModel):
    name: str = Field(description="person name")
    age: int = Field(description="person age")
```

### Create parser

```python
from langchain.output_parsers import PydanticOutputParser

parser = PydanticOutputParser(
    pydantic_object=Person
)
```

### Get formatting instructions

```python
format_instructions = parser.get_format_instructions()
```

### Prompt

```python
prompt = PromptTemplate(
    template="""
    {format_instructions}

    Tell me about:
    {query}
    """,
    input_variables=["query"],
    partial_variables={
        "format_instructions": format_instructions
    }
)
```

### Invoke

```python
result = chain.invoke({
    "query": "John is 25 years old"
})

print(result)
```

Output:

```python
Person(
    name='John',
    age=25
)
```

# StructuredOutputParser (Older Approach)

Earlier LangChain versions commonly used:

```python
from langchain.output_parsers import StructuredOutputParser
from langchain.output_parsers import ResponseSchema
```

Example:

```python
response_schemas = [
    ResponseSchema(
        name="name",
        description="person name"
    ),
    ResponseSchema(
        name="age",
        description="person age"
    )
]

parser = StructuredOutputParser.from_response_schemas(
    response_schemas
)
```

Get instructions:

```python
format_instructions = parser.get_format_instructions()
```

Parse:

```python
result = parser.parse(llm_output)
```

Output:

```python
{
   "name": "John",
   "age": 25
}
```

### Status

This approach still exists in some versions but is largely superseded by:

* `PydanticOutputParser`
* Model-native structured output

---

# Modern LangChain (Recommended)

Most modern models support structured output directly.

Example with OpenAI:

```python
from pydantic import BaseModel

class Person(BaseModel):
    name: str
    age: int

structured_llm = llm.with_structured_output(Person)

result = structured_llm.invoke(
    "John is 25 years old"
)

print(result)
```

Output:

```python
Person(
    name="John",
    age=25
)
```

Advantages:

* No prompt engineering for JSON.
* Validation handled automatically.
* More reliable than parsing text.

This is the preferred approach in recent LangChain versions.

---

# Output Parser Comparison

| Parser                     | Output Type     | Use Case                  |
| -------------------------- | --------------- | ------------------------- |
| `StrOutputParser`          | String          | Plain text                |
| `JsonOutputParser`         | Dict/JSON       | JSON responses            |
| `PydanticOutputParser`     | Pydantic Object | Strong validation         |
| `StructuredOutputParser`   | Dict            | Legacy structured parsing |
| `with_structured_output()` | Pydantic Object | Modern recommended method |

# Current Best Practice (2026)

For new LangChain projects:

1. Use `llm.with_structured_output(MySchema)` whenever the model supports it.
2. Use `PydanticOutputParser` when you need parser-based validation.
3. Use `JsonOutputParser` for lightweight JSON parsing.
4. Avoid `StructuredOutputParser` unless maintaining older codebases.

The line you mentioned:

```python
from langchain.output_parsers import StructuredOutputParser, ResponseSchema
```

is from the older parser-based workflow. In modern LangChain, the equivalent pattern is usually a Pydantic schema plus:

```python
structured_llm = llm.with_structured_output(MySchema)
```

which is simpler and more reliable.
